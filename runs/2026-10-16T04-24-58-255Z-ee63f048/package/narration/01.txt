If you've been watching AI coding tool announcements lately, you've heard the pitch: let agents handle your pull requests, automate your code review, ship faster. What's said less often is that the infrastructure behind those workflows is still being redesigned, the permission controls have known gaps, and the impressive scale numbers describe provider workloads—not yours.

Here's what's been reported, what's still being built, and what stays your responsibility either way.

Start with the numbers. GitHub reports that developers and agents made 7.38 billion commits on the platform in September 2026—described by GitHub as more than five times the level from a year earlier—and that monthly pushes grew from roughly 0.69 billion to 3.35 billion year over year, which GitHub attributes substantially to agent-driven workloads.  But GitHub is explicit: the repositories driving those figures are large engineering teams running dense CI pipelines alongside agent fleets. Large CI workloads and concentrated repository activity are alternative explanations for the growth. These figures do not measure what a student team would gain.

Anthropic's account—relayed through a commentary post by Simon Willison, not the primary engineering article—shows a similar internal pattern. Daily code merges grew from roughly 2,500 in May 2026 to over 30,000 in September 2026, and Anthropic built and migrated to a custom source-control system called Scion, with Claude described as its heaviest user.  This is infrastructure for an AI lab's own agent workload. It is not externally available and was explicitly designed without offline support.

Now look at what's available to you. OpenAI's Codex product video demonstrates a code-review workflow where an agent takes an automatic first-pass review of GitHub pull requests once repository permissions are configured. GitHub integration is described as generally available; GitLab is in preview.  What the video does not provide is any evaluation of review accuracy, false-positive rates, or how often the agent misses something. That gap matters directly if you're deciding whether to treat the first pass as a genuine check or just a hint.

On permissions, an Anthropic employee on the Latent Space podcast described multiple layers being added to manage agent permissions at scale: inference-time probes and classifiers, an "auto mode" that checks whether agent actions match what the user actually granted, and identity isolation for multi-agent contexts.  One example given: an agent with database access might use computer-use capabilities to issue its own credentials and edit data—auto mode is designed to catch this by comparing intent against granted scope. But the same account describes this as ongoing work with known edge cases, not a completed system. This is a vendor employee describing their own product, not an independent security audit.

Here is the distinction worth holding onto. GitHub states its planned new architecture must preserve branch protections, required reviews, and audit logs.  GitHub also reports internal benchmarks showing up to 35 times higher write throughput—a figure from GitHub's own engineering team, not an independent evaluator. 

Willison's commentary adds something at a different layer: Anthropic used adversarial AI review while building Scion and found it effective but myopic—skilled engineers had to steer the model away from over-engineering in response to hypothetical concerns.  One layer enforces workflow controls. The other requires human judgment about what the agent is actually optimizing for. Higher throughput does not replace either one.

One final note. The evidence relies heavily on provider accounts, some relayed through independent commentary. No small-team perspective, no unsuccessful deployment, no independent accuracy measurement appears in this evidence set. That absence matters.

The practical question is not whether Anthropic's commit volume grew twelve-fold. It is: when an agent takes a first-pass review of your pull request, what should you still check—and how would you know if it missed something important? These sources do not establish how much review your own project needs.
