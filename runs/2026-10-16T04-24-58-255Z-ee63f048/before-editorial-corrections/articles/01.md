# The Infrastructure Underneath Your Agent: What Providers Are Rebuilding and Why It Matters

*As of 16 October 2026*

The code you push today may be traveling through infrastructure that didn't exist six months ago—rebuilt from scratch because AI agents broke assumptions that human developers never tested. At least two major providers have already redesigned core development tooling to handle agent-scale workloads, and a third is adding agent-assisted code review as a shipped feature. These are real changes, but the evidence for each is uneven, and most small teams will encounter them indirectly, if at all.

---

## The scale that forced the rebuild

GitHub's engineering blog published activity data in early October 2026 that reframes what "normal" Git usage means. According to GitHub's own figures, developers and agents made approximately 7.38 billion commits on the platform in September alone—more than five times the number from a year earlier—while monthly pushes grew from about 0.69 billion to 3.35 billion year over year [01-c1]. The blog attributes much of this growth to agent-driven workloads and describes the consequence clearly: an agent committing after every action turns ordinary push latency into a per-agent throughput ceiling, a problem that would be invisible to any human developer working alone.

GitHub's response is an architectural redesign in progress. The core change is to separate durable storage from the compute layer that serves read requests, allowing each to scale independently. The company reports internal benchmarks showing up to 35 times higher write throughput—but this figure comes from GitHub's own team describing work that is not yet complete, so it should be treated as an attributed performance claim rather than an independently verified result [01-c6].

Anthropic, meanwhile, has reportedly already finished a comparable migration. According to Simon Willison's notes summarizing an Anthropic engineering post—note that Willison is the intermediary here, not an independent auditor—Anthropic's daily code merges grew from roughly 2,500 in May 2026 to over 30,000 in September 2026, a 12x increase in about four months. The company built and migrated to a custom source-control system called Scion, designed around agents rather than humans, with Claude described as "by far the heaviest user" [01-c2]. The Scion system has no offline support, a design choice that would be unacceptable for human developers but is irrelevant for an always-online agent.

## Where human oversight is structurally at risk

Both providers frame their infrastructure redesigns explicitly around preserving existing governance controls. GitHub's post states that the new architecture must keep branch protections, required reviews, and audit logs intact as agent volume scales—describing this as a precondition for teams to trust automation at all. Anthropic's language, as reported by Willison, similarly emphasizes keeping people in control of their code [01-c5].

This framing is worth taking seriously. It suggests that both organizations recognize human-oversight mechanisms as the part of the stack most at risk of being quietly eroded by volume. An agent fleet pushing thousands of branches per hour can saturate merge queues, overwhelm reviewers, and degrade the signal value of required-review policies without anyone disabling those policies. The infrastructure changes are meant to keep the controls functional at scale, but the controls themselves are not being strengthened—they are being preserved against a new threat.

OpenAI's Codex product video adds a third data point. The video demonstrates a code-review workflow in which an agent automatically takes a first pass at GitHub pull requests once repository permissions are configured, with GitLab support described as in preview [01-c3]. The video shows the user interface and describes the feature as generally available for GitHub, but it does not report on review accuracy, false-positive rates, or how the agent performs on unfamiliar codebases. That is a meaningful gap: an automatic first-pass review that flags the wrong things at high volume could add noise faster than it removes it.

## The permission problem is acknowledged but unsolved

A Latent Space podcast episode published in late September 2026 features an Anthropic employee describing multiple layers of safety infrastructure being added to the Claude Code harness: inference-time probes and classifiers that examine internal model activations, an "auto mode" that checks whether agent actions match user-granted permissions, and identity isolation mechanisms for multiplayer agent contexts [01-c4]. The speaker is an Anthropic employee with clear vendor interest, and the transcript was produced by a publisher-timestamped method rather than manual transcription, so all passages are treated here as paraphrases.

What stands out in that account is not the sophistication of the safety stack but the candor about its incompleteness. The speaker describes the surface area of permission and visibility problems as "like an iceberg"—vast beneath the surface—and gives concrete examples: an agent in one channel that can message another channel, raising questions about whether data can be exfiltrated across permission boundaries; an agent that could theoretically use computer use to issue its own database credentials in order to complete a task the user never explicitly authorized [01-c4]. These are described as ongoing engineering challenges with known gaps, not as solved problems.

## What this evidence cannot tell you

The sources in this assessment have real limitations. The Anthropic source-control story reaches us through Willison's commentary post, not the primary engineering article; the underlying Anthropic post is not directly in evidence. The OpenAI video is a product demonstration, not a measurement. The podcast speaker's observations reflect internal Anthropic use, which differs from a student developer's environment in almost every relevant dimension.

More importantly, none of these sources represent the experience of small teams, students, or unsuccessful deployments. The infrastructure changes described here are almost entirely relevant to large organizations running agent fleets at scale. Most individual developers interact with GitHub through standard clients and will not see or configure anything described in the architectural redesign. Whether the Codex code-review feature changes your daily experience depends on whether you use that product and whether the automated review quality is high enough to be worth reading.

## The implication worth sitting with

If platforms are already redesigning source control around agents as the primary users—with Claude described as Scion's heaviest user and human offline support explicitly deprioritized—then the governance question for small teams is not whether to enable AI agents, but which controls to verify are still functioning once you do. Branch protections and required reviews are only meaningful if a human actually reads the diff before approving. The open question is: when agent-generated code fills your review queue, what does your team's review practice actually become?
